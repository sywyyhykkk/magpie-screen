# Magpie Screen 独立固件 0.3.6

目标板：Waveshare ESP32-S3-Touch-AMOLED-2.16（CO5300 480×480、QMI8658、CST92xx、AXP2101、16 MB Flash、8 MB OPI PSRAM）。

开发板经 Wi-Fi 直接读取 Magpie，不需要运行本仓库的 Node 服务、Mac 伴随程序或连接 USB 数据。Magpie 服务本身仍须运行且能从局域网访问。

## 配网与配置

1. 首次刷入后，已有 Wi-Fi 凭据会保留。没有凭据时自动开启临时配网热点；任何时候长按右侧 GPIO18 键 3 秒也可开启。
2. 屏幕显示热点名称、热点密码／配置访问码和地址。用手机连接热点，打开 `http://192.168.4.1/config`；已经联网时可打开 `http://设备IP/config` 或 `http://magpie-screen.local/config`。热点开放 10 分钟，短按按键可退出屏幕提示。
3. 首次在页面输入屏幕上的配置访问码，同一浏览器、同一访问地址会记住访问码；可点击“忘记此浏览器的访问码”清除。已联网时显示当前 Wi-Fi，点击“切换 Wi-Fi”再填写 2.4 GHz 网络。Wi-Fi 凭据仅保存于开发板 NVS。更换网络后，查看屏幕上的新 IP。
4. 在 Magpie 开启「设置 → 网络与共享 → 在局域网上共享」。填入 `http://Magpie主机的局域网IP:3425` 和允许读取额度、用量及路由的 API Key。本版连接可信局域网 HTTP，不接受回环地址、路径或 HTTPS。
5. 保存后等待首次数据采集，再点击“刷新数据”加载账号选项，选择供应商、账号与窗口并保存。指定账号／窗口不存在时显示未知，不自动换成别的账号。账号标识兼容旧桥接的稳定 ID。

配置页面直接存放在固件内，无 CDN 或 Node 运行依赖。API Key 与 Wi-Fi 密码不会从配置接口回显；留空 API Key 表示保留旧密钥，清除需勾选“清除已保存 API Key”。旧 USB 配对密钥保留，可供已有维护脚本使用。

## 三页与交互

面向屏幕、USB 在下方时，顶部三个实体键从左到右：

| 按键 | 短按 | 长按 |
| --- | --- | --- |
| BOOT / GPIO0 | 1：液体余量 | 上电按住仍进入芯片下载模式 |
| PWR / AXP2101 | 2：实时路由 | 保留 PMU 长按关机 |
| GPIO18 | 3：今日概览 | 3 秒开启配置提示和临时热点 |

熄屏后的首次按键只唤醒，不同时换页。触摸及明显移动也可唤醒。三页文字与图标在旋转停稳后按 90° 翻正，液面独立跟随重力。

- **液体余量**：真实额度控制液量，Codex 灰黑、Claude 橙色，IMU 控制倾斜和惯性。额度变化平滑升降；明确的新重置记录显示重置提示，只有液位回升时显示额度恢复，不推断使用了重置卡。
- **实时路由**：显示最多四个实际目的地，按新请求、尝试、响应、完成播放有限次动画。默认过滤后台调用。首次连接、失败恢复、进程或序列变化只建立基线，不回放历史。缓存最近最多 96 个路由，每条最多 8 次尝试，每次最多 12 个动画事件。
- **今日概览**：显示含读写缓存的总 Token、输入／输出／缓存、请求数、USD 估算、成功率、缓存命中率、输出速度和供应商汇总。超过三个供应商时合并其他。

网络请求在独立 FreeRTOS 任务执行。仅提取所需 JSON 字段，不保留提示词、目录等内容。USB 默认额度每 10 秒、用量每 15 秒、路由每 1 秒轮询；额度接口等待可能使同一采集任务中的其他请求延迟。电池亮屏每 30 秒、熄屏每 60 秒轮询三个接口。

**Magpie 0.1.1336 的局域网路由范围**：全量 `/v1/magpie/trace` 仅允许本机访问。收到 403 后，固件自动改用公开的 `/v1/magpie/usage/requests?period=today&limit=100` 发现最近最多 4 个有网关请求的会话，再逐个读取 `/v1/magpie/route?session=…`；不再重复请求被拒绝的 trace。会话发现最多每 10 秒一次，电池下跟随更低的采集频率。首次发现的会话只建立基线。

因此局域网路由页显示这些会话的**最新请求**，不保证覆盖全部并发请求；新会话通常在首次请求完成后才会出现，快速请求可能跳过中间状态。同一供应商、模型的账号也无法由这个接口区分。配置状态和屏幕的 `SESSIONS` 标签明确标示这个范围。此模式始终不需要 Mac 伴随程序。

断线保留最后读数并显示 `STALE`，不清空液位；重启后的首次读数尚未取得时显示未知。每个接口单独记录失败和恢复状态。

## 显示与电源

| 策略 | USB 输入有效（包括同时有电池） | 仅电池／PMU 状态未知 |
| --- | --- | --- |
| 默认亮度 | 70%（179/255） | 40%（102/255） |
| 调暗 | 熄屏前 30 秒 | 无活动 30 秒 |
| 默认熄屏 | 5 分钟 | 2 分钟 |
| 新业务活动唤醒 | 默认开启，可关闭 | 关闭，后台更新 |
| 常亮 | 默认关闭，可开启 | 始终自动熄屏 |

亮度范围 10–255，熄屏时间 30–3600 秒。短超时的调暗时刻为超时的一半；设置分别保存。滑块松开可预览当前供电模式的亮度 5 秒，点击保存后持久生效。

有效活动包括按键、触摸、超过噪声门槛的移动、新路由状态、实际额度／统计变化和新重置记录；相同接口响应、采集时间及液体余波不重置计时。USB 关闭“新业务活动唤醒”后，活动只延长已经点亮的屏幕。电池模式同样只延长亮屏，不从熄屏唤醒。

液体平稳且显示数据未变化时停止绘图。熄屏发送 CO5300 关显示／睡眠命令，暂停液体计算及像素传输；Wi-Fi 与输入检测继续。唤醒显示最新值，不补播休眠期间动画。开启 USB 常亮仍会停止静止重绘，但 OLED 持续显示固定内容仍有烧屏风险。

AXP2101 分别检测电池接入、USB 输入、充电／充满、电量和电压。无电池时不显示虚假百分比。电池低于等于 10% 时亮度限制在 38/255；仅电池供电且电压连续 30 秒低于 3300 mV 时受控关机。固件保留现有充电电流、电压和保护参数，配置状态接口提供芯片原始设置值；更改充电参数前需确认电池规格，1000 mAh 容量不足以确定这些参数。

## OTA 与构建

设备 `/config` 选择构建生成的 `firmware.bin`，通过受访问码保护的 `/update` 写入备用 OTA 应用分区，校验成功后重启。不要选择 bootloader、partitions 或整片备份。首次烧录、分区变动或故障恢复仍使用 USB。

```sh
pio run -d firmware
pio run -d firmware -t upload --upload-port /dev/cu.usbmodem21101
```

本机 PlatformIO：`/tmp/magpie-screen-flash-tools/bin/pio`。应用固件：`firmware/.pio/build/liquid/firmware.bin`。刷写前停止占用串口的旧 Node 桥接。原厂备份仍在被忽略的 `device-backups/original-2026-10-23/`；不需要擦除整片 Flash。

0.3 固件拒绝旧桥接的 `state`／`config` 命令，防止覆盖独立采集的数据；旧版网页预览与 0.2 桥接代码保留供调试。维护接口 `/api/config`、`/api/status`、`/api/wifi`、`/api/preview`、`/api/wake`、`/api/refresh` 和 `/update` 均要求 `X-Magpie-Key`（设备配置访问码或旧配对密钥）。

## 驱动依据

引脚与驱动初始化依据 [Waveshare 官方示例](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-2.16/tree/225a62bff11b5d0a0b607873860d39485a9a9685/examples/arduino)，Magpie 协议依据 [v0.1.1336 网关](https://github.com/yetone/magpie/blob/v0.1.1336/internal/gateway/gateway.go)。依赖版本锁定在 `platformio.ini`，保持 Arduino 2.0.17 与 GFX 1.5.9 兼容。`labels.h` 为预生成标签，日常构建不需要 Pillow。

### 0.3.1 显示

文字使用预生成的灰度字形，图标由网页同源 SVG 生成，按透明覆盖率混合到背景。辅助文字为 18–22 px，额度说明为单行 22 px；取消设备端 USB、调试状态和页码点。路由页与网页同时移除底部状态栏。UI 覆盖层使用约 675 KiB PSRAM，像素传输仍使用双 480×24 DMA 缓冲。液面插值在 0.3.3 中撤回，恢复原有整数查表绘制路径。

资产重新生成：安装 Pillow、resvg-py 后运行 `python scripts/generate_ui_assets.py`（当前字体路径为 macOS STHeiti Medium）；日常构建直接使用提交的 `ui_assets.h`。

### 0.3.2 额度说明修正

额度窗口名称及路由来源复制到持久数据文档，避免 HTTP 响应释放后显示残缺字符。额度说明按可见字形边界排列，圆点左右各 12 px，中英文按视觉中线对齐。`python3 firmware/test/quota_string_test.py` 验证真实额度适配函数在 200 次响应释放和内存复用后仍保留窗口名称（需 C++17 编译器和已安装的 PlatformIO ArduinoJson 依赖）。

### 0.3.3 液面动画回退

撤回 0.3.1 引入的液面高度与颜色逐像素插值，恢复原有整数查表路径，响应实机动画闪烁反馈。保留字体抗锯齿、图片、自动翻正和 0.3.2 额度说明修正。

### 0.3.4 额度窗口光学对齐

根据实屏反馈，将额度窗口文字下移 2 px，中文与分隔点保持原位置。


### 0.3.5 配置体验、路由 ID 与旋转过渡

配置页显示当前连接的 Wi-Fi，提供切换和取消；删除页面选择，保存设置不覆盖当前实体按键选择的页面。液体黏性和后台路由开关补充对应页面、作用范围说明。访问码在认证成功后保存于当前浏览器的 localStorage，重新打开时自动验证，收到 401 时清除；浏览器或访问地址变化后需重新输入。

Magpie 的请求 ID 超过 32 位范围。会话发现的 `route_id` 判断以及路由缓存排序、淘汰统一使用 64 位 ID，修复路由通道显示连接成功却没有目的地的问题。内容翻正采用与 Web 预览相同的 420 ms 缓动曲线，走最短旋转方向，支持动画中重新转向；液体仍独立跟随重力。动画期间持续绘制，结束后恢复静止停绘。

验证：19 项 Node 测试、Web 构建、固件构建通过；`route_session_test.py` 覆盖大 ID 会话发现、首次基线、新事件与缓存排序淘汰，`orientation_test.cpp` 覆盖过渡、最短方向、动画中转向和计时回绕，额度字符串生命周期回归通过。macOS 本机若默认 SDK 与编译器不匹配，使用 Xcode 内配套 SDK 运行 C++ 测试。

2026-10-23 已通过 OTA 更新到实机 0.3.5，确认设置保留、三个采集通道成功且路由有有效目的地。浏览器验证刷新自动登录、已连接 Wi-Fi 展示、切换展开与取消。未实际操作换网；旋转动画已部署，物理转动观感待现场确认。

### 0.3.6 路由真实账号显示

开发板配置的“页面与液体”区域新增“显示真实账号”，默认关闭。开启后，第 2 页优先显示路由接口返回的账号名称；会话兼容模式只使用相同会话、请求 ID 和供应商的已完成请求账号，且只标注最后一次尝试，未取得账号时继续显示编号。设置保存在设备，账号名称仅在内存中使用。切换开关清空旧路由缓存并重新读取。
